# pa-client

The shared daemon transport.

## Scope
The client half of the daemon wire protocol, extracted from `pa-tui`'s transport: the JSONL supervisor client (`daemon_client`: connect and `daemon_hello` handshake, `type: "command"` envelopes matched by envelope id, non-response frames forwarded as events; bounded connect/handshake retries; `request`/`request_ok`/`request_ok_via_supervisor` with the TS default timeout classes; the `daemon_closing` update-resume contract; typed refusal classification — `is_daemon_rejection`, `is_daemon_timeout`, `is_daemon_unreachable`, `is_kernel_not_running`, `is_update_restarting_rejection`, `rejected_provider_unauthenticated`, `RequestRejected` — for the callers' error paths) and the direct worker link (`direct_transport`: the capability-gated direct-attach ticket path — `GetDirectWorkerTransport` ticket validation, `peer_auth` handshake, the live link and its reader/writer pumps; every failure degrades silently to supervisor routing). The two modules share crate-internal state (`Shared`, `client_event_from_value`, the direct link set) and keep it crate-internal.

## Non-goals
No wire vocabulary of its own: every frame is a `pa-types::daemon` type, and the crate depends on `pa-types` only. No engine, session, settings, auth, model discovery, or update logic; no process supervision — clients of this crate connect to a running daemon, never spawn one. No UI: rendering, keybinding, and composition concerns stay in `pa-tui`/`pa-cli`. `pa-cli`'s own daemon client (its startup, discovery, and behavioral wiring) is a separate, not-yet-converged copy; adopting this crate there is future thin-client work, out of scope here.

## Public API
`daemon_client::{DaemonClient, DaemonClientEvent, DaemonClosingUpdate, DaemonClientOptions, DEFAULT_REQUEST_TIMEOUT_MS, LONG_RUNNING_REQUEST_TIMEOUT_MS, is_daemon_rejection, is_daemon_timeout, is_daemon_unreachable, is_kernel_not_running, is_update_restarting_rejection, is_command_not_sent, is_command_result_uncertain, rejected_provider_unauthenticated, CommandNotSent, CommandResultUncertain, RequestRejected}` — the attach/request surface pa-tui consumes and re-exports under `pa_tui::daemon_client`. `DaemonClient::shutdown`/`join_tasks` add true teardown: idempotent, clone-correct abort of the supervisor reader, the writer pump, and every direct-link pump; the shared reader-dead watch flips BEFORE the sweeps so a request racing shutdown resolves promptly either as a swept uncertain delivery (registered) or a refused non-delivery (post-flip). The join is cancellation-safe (a dropped join future re-inserts its in-flight handle; a later call resumes), drains exactly the REGISTERED tasks to real completion, and leaves the connection owning zero registered tasks/sockets — caller-owned futures (an in-flight upgrade handshake, an outstanding request) settle or drop on their own, and a caller wanting one-shot exactness settles its own operations before the final join (the handles live in a per-connection set shared by every clone; `close`/`hard_close` keep their historical behavior and nothing runs on `Drop`).

`DaemonClientOptions` (opt-in, defaulting to the historical behavior) carries: the lossless raw outbound tap — a separate channel receiving every decoded post-handshake application frame verbatim and in per-socket wire order from the supervisor reader and the direct reader pumps (unknown frame types and full event meta included; handshake, auth, and id-correlated response frames never appear; the unbounded channel must be drained); the inbound supervisor frame byte cap (a frame beyond it tears the transport down and fails every pending request as an uncertain delivery); and the pending-request cap (a request beyond it refuses the send as a provable non-delivery). `CommandNotSent`/`CommandResultUncertain` classify request outcomes by proven delivery state: not-sent only when the writer provably never queued the line, uncertain once it was queued (socket loss in flight, post-write timeout — always the failure sweep's conservative class) or when the direct link answered `Wait`. The daemon's own `DaemonErrorInfo::CommandResultUncertain` refusal stays a separate `RequestRejected` class. The direct-transport half (`DirectLink`, `DirectState`, `connect_direct`, ticket validation, the capability constant) is crate-internal by design: only `DaemonClient`'s `upgrade_direct`/`drop_direct`/`direct_session_id`/`close`/`hard_close` methods expose it.

## Depends on
`pa-types` only (plus anyhow/serde_json/tokio for the socket plumbing).

## Ownership

The daemon transport is owned by this crate; `pa-tui` re-exports `daemon_client` so its existing `crate::daemon_client` callers and `pa_tui::daemon_client` users keep their paths. The extraction from `pa-tui` is a move with no wire or behavior change.
